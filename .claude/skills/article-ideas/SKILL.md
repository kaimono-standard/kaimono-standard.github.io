# 記事案を出す（調査 → 複数レビュー → 絞り込み）

目的は「書けば読まれて、クリックされて、しかも事実で書ける記事」を複数見つけること。思いつきや知識だけで決めない。**調べた根拠（URL）がない案は出さない**。1人の判断で決めず、視点の違うレビュアーに独立に採点・反論させ、練り直してから絞る。

このサイトの収益は楽天市場と Amazon の商品リンクだけ。記事はメーカー公式の仕様で比べ、実機レビューはしない。だから良い案の条件は「需要がある」だけでは足りず、「公式の数値が文字で取れる」「楽天に公式店か大手の取り扱いがある」「規制に触れずに書ける」まで揃っている必要がある。

## 全体の流れ

| # | 工程 | 担当 | 成果物（`_ideas/<日付>/`、git 管理外） |
|---|---|---|---|
| 1 | サイトの現状を読む | Claude（script） | `context.md` |
| 2 | 調査（4系統を並行） | 調査サブエージェント×4 | `research-*.md`（候補と根拠URL） |
| 3 | 候補を1つの表にまとめる | Claude | `candidates.json`（20〜40件） |
| 4 | 1回目の独立レビュー | レビュアー×5（サブエージェント4＋Codex1） | `reviews/round1-*.json` |
| 5 | 練り直し | Claude | `candidates.json` を更新（切り口・型・製品の差し替え） |
| 6 | 2回目のレビュー（上位だけ） | 同じレビュアー | `reviews/round2-*.json` |
| 7 | 絞り込みと提出 | Claude | `ideas.md`（最終案） |

既定では最終案を **8本**出す（ユーザーが本数を言えばそれに従う）。

## 1. サイトの現状を読む

```bash
node .claude/skills/article-ideas/scripts/context.mjs > _ideas/<YYYY-MM-DD>/context.md
```

既存記事（型・カテゴリ・製品ブランド）、担当執筆者ごとの本数、最新の閲覧レポート（`_reports/`）の検索語と読まれたページ、今日から8週間の季節・イベント（`assets/season-calendar.json`）を1枚にまとめる。調査サブエージェントとレビュアーには、このファイルを必ず渡す（重複を避け、新旧比較の元ネタを拾うため）。

閲覧レポートが古い（7日以上前）なら、先に `npm run analytics` を実行する。

## 2. 調査（4系統を並行で）

`references/research-sources.md` を読み、次の4つを**別々のサブエージェント**（general-purpose）に同時に投げる。1つにまとめると、最初に見つけた方向に引っ張られるため。各エージェントには `context.md` と `research-sources.md` の該当節を渡し、「候補を最低8件、1件ごとに根拠URLと“なぜ今か”を1行」で返させる。

1. **いま売れている・伸びている**：楽天市場ランキング（ジャンル別・デイリー／リアルタイム）、検索の伸び（Googleトレンド、Yahoo!リアルタイム検索）、価格.comの注目ランキング（手がかりとして）
2. **これから来る（新製品・新しい習慣）**：直近60日のメーカー新製品リリース（PR TIMES、各社ニュースルーム）、発売予定、SNSやニュースで話題になり始めた生活の変化。**新旧比較の候補**（新型が出て旧型が公式店・大手に残っているもの）もここで拾う
3. **季節・イベント**：今日から4〜8週間後に需要が立つもの（`context.md` の季節欄を起点に、楽天スーパーセール・お買い物マラソン・プライムデー・ブラックフライデー・新生活・防災・寒暖など）。記事は公開から検索に乗るまで時間がかかるので、**いま流行っているものより少し先**を狙う
4. **自サイトの検索データと隙間**：Search Console の検索語のうち、表示はあるのに合う記事がないもの、読まれている記事の周辺（同じ読者が次に買うもの）、既存の5機種比較から作れる新旧比較

ジャンルは縛らない。家電・食品・日用品・美容・ファッション小物・ベビー・ペット・アウトドア・ホビーなど、楽天で買えるものなら何でもよい。

## 3. 候補を1つの表にまとめる

4つの結果を `candidates.json` に統合する（形式は `references/review-rubric.md` の末尾）。同じ商品群は1件にまとめ、根拠URLは全部残す。**根拠URLが1つもない候補はここで捨てる**。候補ごとに、型（`comparison` 5製品比較／`version` 新旧比較）の見込みと、担当に合いそうな執筆者（`_editorial/editors.json`）を仮で入れる。

## 4. 1回目の独立レビュー

`references/review-rubric.md` の5つの視点で、**互いの結果を見せずに**採点させる。4視点はサブエージェント（general-purpose）を同時に起動し、1視点は Codex に任せる（別のモデルに見させることで、同じ見落としを重ねない）。

```bash
node .claude/skills/article-ideas/scripts/codex-review.mjs _ideas/<YYYY-MM-DD> --lens contrarian --round 1
```

| 視点 | 担当 | 見るもの |
|---|---|---|
| demand（需要と時期） | サブエージェント | 検索される量と伸び、公開から検索に乗るまでの時間に間に合うか |
| monetization（収益とリンク） | サブエージェント | 楽天の公式店・大手の取り扱い、価格の出し方（クーポン前提でないか）、Amazon の取り扱い、単価 |
| verifiability（裏取りと規制） | サブエージェント | 公式の数値が文字で取れるか、薬機法・健康増進法・景品表示法・PSE などに触れないか |
| editorial（独自性と執筆者） | サブエージェント | 競合記事との差、このサイトの型で書けるか、どの執筆者の視点が活きるか、既存記事との重複 |
| contrarian（反対意見役） | **Codex** | 各案の一番弱いところを指摘し、「やめるべき理由」を必ず1つ書く |

各レビュアーは候補ごとに 1〜5 点と、理由・致命的な問題（kill）・改善案を JSON で返す。サブエージェントには、必要なら実際にページを開いて確かめてよいと伝える（楽天の検索結果、公式ページの有無など）。

## 5. 練り直し

レビューを並べて、次の順に手を入れる。

- **kill が付いた案**：理由が「根拠不足」なら追加で調べる。「規制」「公式数値が取れない」「楽天に公式・大手がない」なら、切り口を変えて救えるか考え、救えなければ捨てる
- **評価が割れた案**（ある視点で5、別の視点で1〜2）：反対意見に答える形で練り直す。例：需要は高いが製品が並行輸入だらけ → 国内正規品に絞った切り口にする
- **似た案が並んだとき**：まとめるか、読者を分けて別の案にする

練り直した内容は `candidates.json` の `revision` に、何を変えたかを1行で残す。

## 6. 2回目のレビュー（上位だけ）

平均点の上位と、練り直した案を合わせて**12〜16件**に絞り、同じ5視点でもう一度独立に採点させる（`--round 2`）。1回目の点数は見せない。

## 7. 絞り込みと提出

最終案は次のルールで選ぶ。

- 5視点の合計が高い順。ただし**どれか1つの視点で2点以下**のものは入れない
- 最終案の中で**ジャンルが3つ以上**に分かれる。**型**は新旧比較が1本以上入るなら入れる。**担当執筆者**は同じ人が3本を超えない
- 最終案の少なくとも2本は、既存記事と関係のないジャンルから選ぶ

`_ideas/<YYYY-MM-DD>/ideas.md` に、`references/review-rubric.md` の「最終案の書き方」の形で書き出し、ユーザーに見せる。ユーザーが選んだ案は、`rakuten-comparison-article` スキルでそのまま記事にする（型・担当・候補製品・注意点を引き継ぐ）。

## やってはいけないこと

- 根拠URLのない案を出す。「〜が流行っているはず」は案にならない
- Amazon のページをボットのように巡回して、ランキングや価格を抜き出す（アソシエイトの規約で禁止）。Amazon は人が見るのと同じ範囲で、取り扱いの有無を確かめるだけ
- レビュアーに他のレビュアーの結果を見せる（独立性がなくなる）
- 1回目で全部決める。必ず練り直しと2回目を通す
- 効能を売りにする案（「痩せる」「肌がきれいになる」）をそのまま通す。健康・美容は、成分表示や容量・価格で比べられる切り口に直すか、捨てる

- `assets/season-calendar.json` — 例年の季節・イベント（日付は毎回公式発表で確かめる）

- `scripts/codex-review.mjs` — Codex に1視点のレビューをさせる
