# 比較記事の編集ルール

このファイルは Codex の下書きプロンプトにそのまま含める。読み手は「台帳（facts.json）と完成例（exemplar.tpl.html）を渡された執筆者」。

## 記事の役割

読者は「○○を買おうと思っているが、どれにするか決めきれない人」。記事の仕事は、公式仕様を同じ項目で並べ、用途ごとに候補を1つに絞れるようにすること。売り込みでも感想文でもない。運営方針として**実機レビューをしない**ので、使用感・味・音・耐久性は書かない。

## 構成（exemplar と同一にする）

1. `<header class="review-header">`：カテゴリ、h1、リード文、署名（有無（買いもの標準 編集部）、about.html へリンク）、広告表記
2. `<figure class="review-hero-image">`：5製品の画像リンク（`{{IMG:key}}` `{{ITEM:key}}`）
3. `review-summary`：見出しは「使い方から選ぶと、この5機種」。`audience_axes` の順に5行。`<span>用途</span><strong>短い製品名</strong><em>決め手（台帳の数値か機能）</em>`
4. `#comparison` 比較表：列は `製品 | table_columns… | 掲載時価格`。価格は `{{PRICE:key}}`。表の下に `review-footnote`（`table_footnote` を元に）
5. `#choose` 選び方4点：`buying_points` を `plain-guide` で
6. `#products` 用途別5製品：製品ごとに `review-product`（`header` の p は「〜なら」で終える／h3 は正式名称／写真リンク／本文1段落／`<ul>` に台帳の主要スペック3点／`fit-note`／`caution-note`／`rakuten-button`）
7. `#sources` 出典：製品と同じ順で `official_url` を `official_label` の文言で
8. サイドバー：目次、比較の前提（仕様確認 メーカー公式／価格確認 楽天市場／確認日）、関連する比較（既存記事から2本）

h1 は「○○5機種を比較。軸A・軸B・軸Cで選ぶ」の型。`<title>` は h1 の「。」を「｜」にし末尾に「｜買いもの標準」。meta description は5ブランドを列挙して「メーカー公式仕様を確認して整理しました。」で締める。

## 文体

- です・ます調。一文は60字前後まで。体言止めは表と結論ブロックだけ
- 主語は製品か読者。「当サイトでは」「編集部は」は書かない（署名で足りる）
- 数値は台帳の表記そのまま（`1300W` `約4.3kg` `80〜250℃`）。全角数字は使わない。範囲は「〜」
- 製品の説明段落は「何ができるモデルか」→「主要機能の列挙」→「補足（色数、付属品、発売時期）」の順。3文以内
- `fit-note` は「〜人。」で終える一文。`pick_reason` を言い換える
- `caution-note` は買う前に知るべき事実を1〜2文。`caution_hint` と `unverified`、`variant_note` から作る。欠点探しではなく「この人には向かない」「購入時にここを確認」の書き方
- ボタン文言：`shop_is_official` が true なら「○○公式楽天市場店で見る」、選択式なら「楽天市場で色と価格を見る」、それ以外は「楽天市場で価格・在庫を見る」

## 書いてよいこと・いけないこと

書いてよい：
- 台帳の `specs` `features` `release` `caution_hint` `variant_note` にある事実
- それらから四則演算で導ける事実（「5機種で最軽量」は表の数値が一意に最小のときだけ。同値があれば「○○と並んで」）
- ジャンル共通の一般論で数値を含まないもの（「ワンタッチ式は部品が多く洗う手間が増える」程度）

書いてはいけない：
- 台帳にない数値、時間、温度、枚数、色数
- `unverified` に挙がっている項目の断定。触れるなら「公式仕様に記載はありません」
- 「おいしい」「静か」「使いやすい」など体験を前提にした形容
- 「人気」「売れ筋」「定番」「コスパ最強」など根拠を示せない評価語
- 「〜と言われています」「一般的に〜とされています」。出典のない伝聞は削る
- 他社比較の断定（「A社より速い」）。測定条件が違うので、表の脚注で「各社で測定条件が異なる」と断る
- ラクヨコへの誘導。この記事は楽天市場リンクで完結させる
- 「実機を使用したレビューではありません」「実物の使用感は評価していません」「実機テスト なし」のような断り書き。運営者の判断で記事には載せない。広告表記は「本記事には楽天市場の商品リンク（広告）が含まれます。」の1文だけ。出典欄の説明文も「製品仕様はメーカー公式ページ、商品画像・価格・販売リンクは楽天市場で〈日付〉に確認しました。」で止める
- **見出しやリード文の頭に「結論：」「ポイント：」「出典：」のような『ラベル＋全角コロン』を付けない**。見出しはそのまま文にする（「使い方から選ぶと、この5機種」）。製品ブロックの `<ul>` にある「消費電力：1300W」のような仕様の項目名は例外
- **「楽天アフィリエイト」という語を記事に書かない**（「楽天アフィリエイトを利用」「楽天アフィリエイトの商品検索で確認」「楽天アフィリエイト管理画面で取得」「商品リンクから取得した画像」など）。アフィリエイトは運営側の仕組みであって読者に見せる情報ではない。読者向けには「楽天市場で確認」「楽天市場の商品ページ」「商品リンク（広告）」と書く。価格の確認先も「楽天市場」とする

## プレースホルダ

`<head>` の preconnect、Article の `"image":"{{IMGRAW:先頭製品のkey}}"`、BreadcrumbList（3階層目は h1 と canonical）、先頭ヒーロー画像の `fetchpriority="high"`、全 `<img>` の `width="240" height="240"` は exemplar の通りに付ける。

リンク・画像・価格は台帳から機械的に差し込むので、本文には次の形で残す。`key` は製品の `key`。

- `{{ITEM:key}}` … `data-fallback` の値
- `{{IMG:key}}` … `<img src>` の値
- `{{PRICE:key}}` … 比較表の掲載時価格

`data-affiliate="key"` `rel="nofollow sponsored noopener" target="_blank" href="#"` の属性は exemplar の通りに付ける。この3属性と `data-fallback` が揃っていないと、サイト側の JS がアフィリエイトURLを差し込めない。

## セルフチェック（出力前に確認）

- 製品ブロック・比較表の行・結論の行・出典の行がすべて5つで、順番が台帳と同じ
- 最上級表現（最も／最軽量／最大／最小／いちばん／唯一）を使った箇所は、表の数値で成り立つ
- `{{` `}}` のプレースホルダ以外に未確定の記号（TODO、???、○○）が残っていない
- 各製品の `<ul>` の3点は `specs` にある値だけ
